## Implementation Summary

1. **P0-1** (API reference gaps) can be done in parallel with everything else — it's pure documentation, no code risk.
2. **P0-2, P0-5, P0-6** (auth/MFA correctness) — verify against actual code first; these may already be correct and just under-documented, or may be real bugs. Worth a quick audit before assuming the worst.
3. **P0-4** (WebSocket scaling) blocks any horizontal-scaling rollout — fix before deploying more than one API replica.
4. **P0-3** (admin/RBAC) is the largest scoped effort — worth planning as its own mini-project rather than squeezing into a sprint.
5. P1 items can be tackled opportunistically; P1-5 (Change table pruning) is worth doing before the table gets large enough that a retrofit is painful.
6. P2 items are good "while you're in there" fixes alongside related P0/P1 work.
